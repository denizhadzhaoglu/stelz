# Spot the Brand CLI + MCP

Agent-native CLI and MCP server for the Spot the Brand monitoring API.

Generated by [Printing Press](https://printingpress.dev/) from a single OpenAPI 3 spec (`openapi.yaml`). Re-generate with:

```bash
~/go/bin/printing-press generate \
  --spec ./openapi.yaml \
  --name spot \
  --output ./generated \
  --validate=false
```

Three artifacts are produced:
- `generated/cmd/spot-pp-cli/` → Go binary, `spot` CLI
- `generated/cmd/spot-pp-mcp/` → Go binary, stdio MCP server
- `generated/SKILL.md` → Claude Code skill

## Architecture

```
┌─────────┐   ┌──────────────┐   ┌──────────────────┐   ┌─────────────┐
│ spot    │──▶│ Vercel API   │──▶│ Supabase Postgres│──▶│ scan worker │
│ CLI     │   │ spot-api     │   │ (RLS + RPCs)     │   │ on Railway  │
│ + MCP   │   │ /api/v1/*    │   └──────────────────┘   └─────────────┘
└─────────┘   └──────────────┘
```

Live API URL (production, SSO-protected pilot phase):
- `https://spot-api-eight.vercel.app/api/v1`

Eventually aliased as `api.spotyourbrand.com/v1`.

## Build

Prerequisites: Go 1.23+.

```bash
cd projects/spot-the-brand/cli/generated
go mod tidy
go build -o /tmp/spot ./cmd/spot-pp-cli/
go build -o /tmp/spot-mcp ./cmd/spot-pp-mcp/
```

The binaries are ~18MB and ~20MB respectively (static Go).

## Configure the CLI

```bash
# Save the staff token to the CLI's config
/tmp/spot auth set-token "$(cat .local-token | cut -d= -f2)"

# Verify everything's wired
/tmp/spot doctor
```

The token lives in `~/.config/spot-pp-cli/config.toml`. Base URL is read from the OpenAPI spec's `servers:` section.

## CLI commands

```bash
# List brands you can see
spot brands list

# Brand profile + headline stats
spot brands get --brand-slug stelz

# Health snapshot (scan throughput, FP rate, pending)
spot brands health get-brand --brand-slug stelz

# Recent hits in last 7 days
spot brands hits list-recent --brand-slug stelz --limit 20

# Top hit-producing creators
spot brands top-creators list --brand-slug stelz --limit 10

# Full creator detail
spot brands creators get-detail --brand-slug stelz --handle drinkstelz

# False-positive breakdown
spot brands fp-analysis get --brand-slug stelz

# Brand hashtag pool
spot brands hashtags list-brand --brand-slug stelz

# Add a hashtag
spot brands hashtags add-brand --brand-slug stelz --hashtag nieuwetag --priority 7

# Trigger a priority scan
spot brands scans trigger --brand-slug stelz --scope priority

# Mark a detection as a false positive
spot detections false-positive mark --id <detection_uuid>
```

Add `--agent` for JSON output + non-interactive mode (ideal for piping to other tools or running from Claude Code).

## Vercel SSO protection (pilot phase)

The API project (`spot-api`) has Vercel Deployment Protection enabled. This means random internet traffic gets bounced through Vercel SSO, AND our app-level bearer token check. Two paths to use the API:

**Path A — `vercel curl` (zero config, what works today):**
```bash
cd projects/spot-the-brand/api
vercel curl /api/v1/brands -- -s -H "Authorization: Bearer $(cat ../cli/.local-token | cut -d= -f2)"
```
`vercel curl` auto-generates a protection bypass token using your Vercel CLI auth.

**Path B — generate a permanent automation bypass token:**
1. Open https://vercel.com/meinte-3019s-projects/spot-api/settings/deployment-protection
2. Under "Protection Bypass for Automation" → Add Secret → save the value
3. Put it in the CLI request via `?x-vercel-protection-bypass=<secret>` URL param, or via the `x-vercel-protection-bypass` header

**Path C — make production public (recommended once we're confident in our auth):**
Same settings page → toggle "Vercel Authentication" to OFF for production. The bearer-token check (`SPOT_API_TOKEN`) becomes the only gate, which is sufficient for a private API.

## MCP server

The MCP binary (`spot-pp-mcp`) speaks stdio JSON-RPC. To plug it into Claude Desktop / Cursor / Windsurf:

```jsonc
{
  "mcpServers": {
    "spot": {
      "command": "/path/to/spot-pp-mcp",
      "env": {
        "SPOT_PP_CLI_CONFIG": "/Users/<you>/.config/spot-pp-cli/config.toml"
      }
    }
  }
}
```

The MCP server shares the CLI's config file. So whatever token you set via `spot auth set-token` flows through to the MCP server automatically.

## Iteration loop

When we add/change an endpoint:

1. Edit `openapi.yaml` (the spec)
2. Edit / add the matching `api/v1/...` handler in `../api/`
3. `cd ../api && vercel deploy --prod`
4. Regenerate CLI + MCP:
   ```bash
   ~/go/bin/printing-press generate --spec ./openapi.yaml --name spot --output ./generated --validate=false --force
   cd generated && go build -o /tmp/spot ./cmd/spot-pp-cli/ && go build -o /tmp/spot-mcp ./cmd/spot-pp-mcp/
   ```
5. `spot doctor` to confirm it picks up new operations

The `--force` flag tells printing-press to merge fresh-generated code against any hand-edits in `generated/`. We can hand-edit selectively (e.g. customize output formatting) without losing changes on the next regen.
